# Shelfday Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, with one fresh whole-project review at the end. The user has delegated routine decisions and authorized sequential GitHub pushes.

**Goal:** A usable private daily kitchen workbench with durable stock and portion reconciliation.

**Architecture:** A pure validated reducer produces complete kitchen states. A D1 compare-and-swap repository persists them under platform user identity. React renders the resulting state and submits explicit operations with revision and idempotency keys.

**Tech Stack:** React 19, TypeScript, Vinext, Cloudflare D1, Zod, Node test runner, Sites hosting.

**Spec:** docs/superpowers/specs/2026-11-06-shelfday-design.md

## Global Constraints

- One private kitchen per signed-in user.
- Whole grams, millilitres, or items; dates are explicit calendar dates.
- No expired consumption or negative stock; close requires zero unaccounted portions.
- Sample data is opt-in and visibly labeled.
- Staged verified commits/pushes; no empty or backdated commits.

## Review Focus

- Multiple recipes competing for the same stock: combined demand must not double-count availability.
- Expired stock and date rollovers: allocation excludes expired lots even when total stock appears adequate.
- Stale writes, double submissions and lost responses: no repeated deductions.
- Backup corruption or inconsistent references: reject before replacing durable data.
- Sales after price edits and closed-day changes: retain snapshots, forbid closed-day mutations.
